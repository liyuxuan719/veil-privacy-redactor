PRIVACY ARCHITECTURE / MODEL NOTES

看得见的本地处理，
说得清的能力边界。

VEIL 的核心约束很简单：图片、识别结果与导出文件都不经过服务器。 这份说明解释它怎样做到、会处理什么，以及哪些事情它不能替你保证。

01 / WORKFLOW

两分钟完成一次安全分享

拖放、粘贴或选择截图。超大图片会在本地缩放，以免占用过多内存。

在画布上直接拖出额外遮挡区。沿图片边缘、反光和背景再检查一遍。

04

导出

选择马赛克、强模糊或纯色，再导出全新的 PNG 或 JPEG。

02 / ZERO-UPLOAD

图片没有上传路径

“本地处理”不是一句界面文案，而是由资源路径、运行时和内容安全策略共同约束的架构。

原始图片浏览器内存
→
本地模型同源加载
→
遮挡画布重新绘制
→
安全图片直接下载
  • 运行资源同源OCR、人脸模型和第三方脚本随站点静态资源提供。
  • CSP 限制连接页面只允许连接自身源，外部上传端点会被浏览器拦截。
  • 没有后端接口项目是纯静态站点，不包含图片上传 API、数据库或用户账号。
  • 刷新即清空图片只存在于当前页面内存；本地存储仅保存显示偏好。

03 / DETECTION

四种识别，一条本地流水线

目标本地引擎建议
人脸 TensorFlow.js + BlazeFace 低分辨率或侧脸需手动补框
号码与证件 Tesseract.js 中英文 OCR 旋转、手写与小字可能漏检
车牌 OCR + 规则匹配 异形车牌必须人工复核
二维码 jsQR 像素扫描 严重反光或破损会降低成功率
自动识别是起点，不是保险箱。

模型可能漏掉文字、背景中的号码、镜面反射或屏幕边缘信息。导出前必须人工检查。

04 / SAFE EXPORT

输出一张没有原始元数据的新图片

VEIL 从原图像素重新绘制一块 Canvas，而不是直接修改原文件。因此导出的 PNG/JPEG 不携带原文件的 EXIF、GPS、相机型号与编辑历史。

马赛克

先缩小再放大像素块，默认强度较高，适合常规分享。

强模糊

边缘更自然，但低强度可能保留轮廓，建议配合高强度和扩边。

纯色

最不易从遮挡区域推断内容，适合证件号、住址等高风险信息。

JPEG 是有损格式。每次转发、再次截图或平台压缩都可能改变像素；不要依赖低质量模糊保护高度敏感内容。

05 / BOUNDARIES

VEIL 不能替你保证什么

  • 不能保证不可逆匿名化

    背景、服装、伤疤、文字风格或其他线索都可能重新识别一个人。

  • 不能保证百分之百检出

    识别模型都有误差。工具不会覆盖它没有识别出来的区域。

  • 不是法律或医疗合规认证

    公开材料前，仍应按照所在地区的规则完成必要的人工审查。

  • 不能控制第三方平台

    导出后如何被压缩、转载、缓存或索引，不在 VEIL 的控制范围内。

06 / SELF-HOST

静态托管即可运行

仓库包含 GitHub Pages、Netlify、Vercel、Docker 与通用静态服务器配置。 不需要数据库、API 密钥或构建步骤。

FAQ

常见问题

第一次识别为什么比较慢？

浏览器需要加载 OCR 语言数据和人脸模型。资源会在本地生成缓存，之后启动会更快。

离线时还能使用吗？

完成首次加载并安装 PWA 后，应用与模型可由 Service Worker 提供离线访问。

导出的图片真的没有 EXIF 吗？

VEIL 使用新 Canvas 编码，因此不会复制原文件的 EXIF/GPS 区块。平台后续处理不在控制范围内。

识别结果会保存吗？

不会。刷新页面后图片和遮挡区域都会丢失；只有遮挡样式、格式等显示偏好保存在 localStorage。
